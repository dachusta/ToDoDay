# ToDoDay — Wireframes ключевых экранов

> **Части документации:** [ТЗ](ТЗ-ToDoDay.md) · [Вайрфреймы](Вайрфреймы-ToDoDay.md) · [Контракты](Контракты-ToDoDay.md) · [Приёмка MVP](Приёмка-ToDoDay.md) · [Журнал правок](Журнал-правок-ToDoDay.md) · [Архив скаффолда](Скаффолд-ToDoDay.md) · [README документации](../README-Docs.md) · [README приложения](../README.md)

Версия: 2.4.1 (MVP). Модель экранов — ревизия 2.0: «Дни» хранят планы конкретных дат и повторяющиеся планы, а «Сегодня» показывает исполнение плана и отдельно помечает отклонения: «внепланово», «перенесено» и изменение длительности. Ревизия 2.2.0 добавила статистику по дням (§7.4), группировку истории по дням и счётчики отклонений; ревизия 2.3.0 — перенос выбранных невыполненных дел в следующий проживаемый день (§6); ревизия 2.4.0 — навигацию по предыдущему/следующему дню и read-only просмотр (§1).

Ниже — детальные макеты с аннотациями. Формат: ASCII-схемы + легенда элементов + поведение в состояниях (default / empty / loading / error) + адаптив (mobile / desktop).
Условные обозначения на схемах:

- [ ] — кнопка / кликабельный элемент

- ( ) — radio / чекбокс

- ▾ — dropdown

- ▲▼ — сортировка

- ⚠ — конфликт / предупреждение

- ● — цветовой индикатор дела / дня

- ⋮ — контекстное меню

## 1. Экран «Сегодня» (DayBoard) — основной

«Сегодня» — это факт дня: доска открывает план, выбранный на текущую дату, и показывает его размещения. Любое добавление, перемещение, изменение длительности, замена или удаление планового дела здесь считается внеплановым и не меняет сам план (FR-B-8). План правится отдельно, в редакторе `/days/:id`, куда ведёт «Открыть план».

Аннотации:

- Сетка: 15-мин шаг, крупные линии каждые 30 мин, часовые жирнее.
- Автоскролл к текущему времени при открытии; маркер «сейчас» — красная линия через всю ширину с точкой.
- В шапке: «← Предыдущий день» и «Следующий день →», дата с меткой «Сегодня/Вчера/Завтра», имя плана с акцентной точкой и диапазон. У повторяющегося плана добавляется правило словами («по дням: Пн, Вт…», «1, 15 числа»). Если плана на дату нет — «Без плана» и нейтральная точка; если план удалён — «План дня удалён».
- «Открыть план» показывается только при существующем плане и ведёт в `/days/:id`. Стрелки навигации меняют только просматриваемую дату и доступны всегда; активный день при этом не завершается (FR-C-6). «Завершить день» и «Отменить завершение» доступны только на активном дне.
- «К текущему дню» появляется при просмотре другой даты и возвращает активный экземпляр. На просмотре доска read-only: панель дел, меню карточек, drop и завершение скрыты (FR-C-6).
- Долгий тап (mobile) или правый клик (desktop) на PlacementCard — контекстное меню. На карточке нет чекбокса: статус показывается иконкой.
- Плановое размещение, которое в «Сегодня» передвинули по времени, получает бейдж «перенесено» и подпись «план: HH:mm» с прежним плановым временем; внеплановым оно не считается. Изменение длительности даёт бейдж «длительность» и пару «было → стало» (прежняя длительность зачёркнута), тоже без «внепланово». Дело, добавленное в «Сегодня» из панели или списка, остаётся «внепланово»; у него изменение длительности дополнительно отмечается. Отметки независимы и могут стоять на одной карточке вместе.
- «Убрано из плана (N)» — плановые дела, убранные из факта дня. Они скрыты с сетки и из «Нераспределённых», при завершении становятся пропущенными и могут быть возвращены кнопкой «Вернуть в день» (FR-B-8).
- «Нераспределённые (N)» — размещения с `startMin = null`: сюда попадает всё, что не помещается в интервал дня (FR-B-5).

Поведение:

- Левая панель — ширина 280–320 px, сворачиваемая; поиск и фильтр приоритета живут в ней. На просмотре неактивного дня панель скрыта.

### 1.3 Состояния

| Состояние | Что показываем |
| --- | --- |
| Loading | Skeleton-сетка серого цвета + shimmer (четыре строки) |
| Плана на дату нет | Шапка «Без плана» + нейтральная точка; блок «На этот день нет плана» с подсказкой и CTA «Создать день» и «Взять дело». День виртуален: в Dexie его нет, `activeInstanceId = null`; состояние переживает перезагрузку и не создаёт записи в истории |
| План есть, дел нет | Пустого блока нет: в шапке имя плана, под сеткой подсказка «Возьмите дело из списка» |
| День завершён | Доска только для чтения: drag, меню размещений и «Завершить день» недоступны (`DAY_NOT_ACTIVE`). В шапке, пока живёт снапшот сессии, кнопка «Отменить завершение» (FR-E-3). Стрелки просмотра остаются доступны |
| Просмотр завершённого дня | Над сеткой плашка «Завершённый день — только просмотр», кнопка «К текущему дню». Размещения и статусы — из сохранённого `DayInstance`; меню, drop, панель дел и завершение скрыты |
| Просмотр будущего дня | План материализуется в памяти, плашка «План на будущую дату — только просмотр»; дел в Dexie не появляется. Если плана нет — пустой просмотр |
| Прошедший день без записи | Если на дату есть план — «День не открывался — показан план»; если нет — «За этот день нет сохранённых данных». CTA создания дня в просмотре нет |
| План удалён | В шапке вместо имени плана — «План дня удалён» (i18n `day.planDeleted`), акцентный цвет нейтральный; факт дня и его размещения остаются |
| Error (БД недоступна) | Баннер сверху + кнопка «Повторить» |

Виртуальный день материализуется первым размещением или завершением; создание плана на его дату заменяет пустой день планом. Если после перезагрузки плана на дату по-прежнему нет, пользователь видит то же состояние «Без плана», а не потерянный день (FR-D-6).

Context menu (long-press / right-click), он же клавиатурный путь (Enter/Space на карточке, FR-B-7):

```
┌─────────────────────────────┐
│ ✓ Отметить выполненным      │  ← или «Снять отметку», если уже done
│ ✗ Отметить пропущенным      │  ← или «Снять отметку», если уже skipped
│ ─────────────────────────── │
│ ⏱ Изменить длительность     │
│ 🔄 Заменить дело            │
│ ➡ Переместить в слот…       │  ← клавиатурная альтернатива drag-and-drop (FR-B-2)
│ 🗑 Убрать из дня            │  ← у планового дела факт остаётся в «Убрано из плана»
└─────────────────────────────┘
```

▶ — не статус. Рисунок, пока локальное время внутри интервала размещения. `Placement.status` не меняется (FR-B-6). Чекбокса на карточке нет.

Аннотации доступности: карточка — `role="button"`, `tabindex="0"`, `aria-pressed="true"` только пока её тащат, `aria-label` вида «Зарядка, 08:15–08:30, выполнено», у внеплановой добавляется «внепланово», у перенесённой — «перенесено» и «план: 12:00», у изменённой по длительности — полный текст «изменена длительность: было 30 мин, стало 45 мин» (бейдж на карточке короткий — «длительность»). Список «Переместить в слот…» — `role="list"`, пункт — `role="listitem"`. Стрелки работают внутри этого списка. Перенос объявляется через `aria-live` («Зарядка перемещена в 09:00»).

### 1.5 План и факт

- План дня (`DayPlan`) — один из трёх режимов: конкретный день с датой, повторяющийся по дням недели или числам месяца, заготовка «Без даты». Он хранит `plannedPlacements` — замысел с временем и длительностью.
- Факт дня (`DayInstance`) создаётся из плана на дату. Изменения в «Сегодня» сохраняются только в факте: добавление, замена и удаление помечаются `unplanned`, перенос — `shifted`, изменение длительности — `durationChanged`; сам план не меняется.
- Убранное плановое дело не исчезает: оно получает `removed`, уходит в «Убрано из плана», при завершении становится `skipped` и может быть возвращено в день; отметки переноса и длительности при удалении снимаются.
- Правка плана в `/days/:id` обновляет плановую основу открытого дня, но сохраняет отклонения (`unplanned`/`shifted`/`durationChanged`) и уже выставленные статусы; если план догнал факт, отметка снимается. Завершённая история не переписывается.
- «Без плана» — это ещё не запись в истории: пустой день становится фактом только после первого размещения или завершения.

Карточка дела:

- Полоса цвета слева (4 px).
- Название — 1 строка, ellipsis.
- Приоритет — бейдж справа.
- Длительность + мини-сводка (done/skipped).
- [⋮] — контекстное меню.

Контекстное меню карточки:

```
┌──────────────────────────────┐
│ ✏️ Редактировать             │
│ 📋 Дублировать               │
│ 📊 Статистика дела           │
│ ──────────────────────────── │
│ 🗄 Архивировать              │  ← FR-T-3 (soft-delete)
│ 🗑 Удалить                   │  ← FR-T-6: только для архивного дела
└──────────────────────────────┘
```

Правило разделения действий (FR-T-3 / FR-T-6): «Архивировать» доступно всегда и обратимо (в том же меню у архивного дела — «Вернуть из архива»). «Показать архивные» выключен — в списке только живые дела; включён — живые и архивные вместе. «Удалить» показывается только у архивной строки (фильтр при этом включён, иначе архивных строк не видно); нажатие требует подтверждения «Удалить дело из архива безвозвратно?». У неархивного дела пункт скрыт, а action возвращает CONSTRAINT_VIOLATION.

Аннотации:

- Режимы: «Один день» (`date` задан, правило `none`), «По дням недели», «По числам месяца» (правило `weekdays`/`monthdays`, `date: null`), «Без даты (заготовка)» (`date: null`, правило `none`).
- Дата по умолчанию — сегодня или дата из `?create=` на `/days`. Повторяющийся план и заготовка дату не хранят.
- Чипы Пн–Вс начинаются с первого дня недели из настроек; значения правила остаются 0 = Пн … 6 = Вс. Числа месяца — 1…31.

- Список дел в форме не редактируется: дела добавляются и переставляются в редакторе уже сохранённого плана.
- При попытке сменить дату или режим у плана, открытого в «Сегодня», форма показывает «Дата или режим дня не меняются, пока день открыт. Сначала завершите текущий день.» и не сохраняет.

### 4.2 Валидация (inline, у поля)

| Поле | Правило | Сообщение |
| --- | --- | --- |
| Название | 1–50 символов | «Введите название (до 50 символов)» |
| Дата | `YYYY-MM-DD`, уникальна среди конкретных дней; на дату с завершённым днём новый план не создаётся | «Дата: YYYY-MM-DD» / «На эту дату уже есть день» |
| Время | `HH:mm`, минуты кратны 15, конец позже начала, диапазон 60–1425 мин | «Конец дня должен быть позже начала» / «Время: HH:mm, минуты кратны 15…» |
| Цвет | `#RRGGBB` | «Цвет: HEX #RRGGBB» |
| Правило | не пустое, значения в диапазоне (дни 0–6, числа 1–31) | «Выберите хотя бы один день или число», «Недопустимые значения правила» |
| Конфликты | правило не пересекается с планами того же типа | «Пересечение по дням недели с планом «X»», «Пересечение по числам месяца с планом «X»» |

Неблокирующих предупреждений о «недостижимых» днях в модели 2.0 нет: повторяющийся план задаётся правилом недели или числа, а конкретный день на дату перекрывает его.

- Шапка: название плана, дата (или правило, или «Без даты»), диапазон и «Дел: N». «Добавить дело» открывает `PlanTaskPicker`; «Настройки дня» — ту же `DayPlanForm` с заполненными полями; «Удалить» — подтверждение и возврат к списку.

- В списке — активные дела; поиск по подстроке без учёта регистра, сортировка по названию. Уже добавленные в план показываются отмеченными и не дублируются; архивные и отсутствующие показываются отдельно и не выбираются заново.
- «Готово» добавляет отмеченные дела в «Нераспределённые» (`startMin: null`) с длительностью из дела. Убрать дело из плана можно действием «Убрать из дня» на карточке, а не снятием галочки в этом диалоге.
- Пустая библиотека: «Пока нет активных дел», кнопка «Готово» доступна.

### 4.4 Поведение сохранения плана

- Новый конкретный план сразу появляется в списке и заменяет виртуальный день, если его дата совпадает с текущей; повторяющийся план синхронизирует текущий день, если тот открыт по нему.
- Синхронизация обновляет неизменённые плановые размещения, добавляет новые и убирает из факта обычные `pending`-позиции, удалённые из плана. Внеплановые отклонения, уже отмеченные и убранные позиции сохраняются (FR-D-11).
- Смена начала дня пересчитывает смещения так, чтобы абсолютное время фактических размещений сохранялось; не помещающееся уходит в «Нераспределённые».
- Правка плана на прошедшую дату не меняет завершённую историю: редактор показывает подсказку «Прошедший день: правки не изменяют историю».
- Заготовка «Без даты» используется как основа для нового дня или получает дату/правило при правке; сама она в «Сегодня» не открывается.

Поведение:

- По умолчанию: done → чекбокс стоит, pending → снят, skipped → снят. Нераспределённые входят в список без времени. Внеплановые дела показываются с бейджем «внепланово».
- У неотмеченного дела есть кнопка «Перенести» (иконка `east`, активное состояние — `aria-pressed`). Выбранное дело уйдёт в следующий проживаемый день; в этом дне оно всё равно станет `skipped`, а в новом появится внеплановым. Отметка «выполнено» снимает и блокирует перенос; «Отметить всё» очищает выбор, «Снять всё» — только снимает галочки.
- Подсказка в шапке называет дату: при обычном завершении сегодняшнего дня — завтра, после просроченного — сегодня, при сдвиге — дата нового дня (FR-E-4, ТЗ §2.8).
- Убранные из плана в список не попадают, но в шапке диалога есть подсказка «Убрано из плана: N — будет помечено пропущенным»; при подтверждении они становятся `skipped`.
- Снятие галочки с ранее done — при подтверждении станет skipped.
- Кнопка «Вернуться к дню» — закрывает диалог без фиксации.
- После подтверждения — тост «День завершён» (5 с) с кнопкой «Отменить» и такая же кнопка в шапке доски, пока живёт снапшот сессии (FR-E-3). Отмена восстанавливает снимок отметок и удаляет день, созданный этим завершением, даже если в него уже положили дела.
- Авто-триггер: доп. опция «Пропустить диалог в этот раз». Она не пишет настройки. Постоянный тумблер — только экран настроек (вайрфреймы §8, поле `askToCompleteOnNewDay`). «Вернуться к дню» у авто-диалога тоже ставит разовый пропуск до перезагрузки.
- Пустой (виртуальный) день: диалог не открывается автоматически — «В этом дне нет размещённых дел». Кнопка «Завершить день» на доске остаётся доступной: подтверждение сохраняет день без размещений в историю (FR-D-6).
- «Подтвердить» фиксирует день и оставляет активным завершённый экземпляр; следующий день не создаётся. Кнопка «Завершить и открыть следующий» показана только у ручного диалога и только пока сдвиг в эти сутки доступен (`canOpenNextDay`): она выполняет прежний ручной сдвиг. Для `early` дата нового дня — завтра, для `overdue` — сегодня; план берётся на целевую дату (ТЗ §2.8, FR-C-3).
- Перенесённое дело появляется в новом дне на доске с бейджем «внепланово» (время суток сохраняется, при невместимости — «Нераспределённые»). Если целевой день пропустили, оно материализуется в первый открытый день; в плане нового дня дубль разрешён — это отдельное внеплановое размещение (FR-E-4).

Про строки таблицы (ТЗ FR-S-2, FR-S-5):

- В список попадают только дела, у которых есть хотя бы одно размещение в завершённых днях выбранного периода. Строки «0 размещено / 0 выполнено» не существует: дело, которое не размещали вовсе или размещали только вне периода, в таблицу не показывается.
- «0 вып. · 4 проп. · 0%» — это дело с размещениями в периоде, все из которых пропущены (placed = 4, done = 0, skipped = 4). Рейт 0% и 0/0 — разные вещи: 0/0 даёт прочерк «—» и в таблицу не попадает, потому что размещений в периоде нет.
- Прочерк «—» на прогресс-баре остаётся только для вырожденного случая placed > 0 при done + skipped = 0 (например, всё ещё pending — в MVP для завершённых дней недостижимо).
- Итоговая сводка — семь чисел `OverallStats` (размещено, выполнено, пропущено, внеплановых, перенесено, изменена длительность, рейт), те же на узком экране и на десктопе.
- «Внеплановых» — размещения с `unplanned === true`: добавленные, заменённые или убранные в «Сегодня». «Перенесено» — плановые размещения со смещённым временем, «изменена длительность» — с другой длительностью; в `unplanned` они не входят, но могут встретиться вместе. Все три входят и в итог, и в строку своего дела; в истории дела есть соответствующие отметки, у убранного — ещё и «убрано из плана».
- Блок «По дням» — завершённые дни выбранного периода, новые сверху; строка показывает дату и счётчики (вып./проп. и отклонения, только при значении > 0). Клик открывает страницу дня (§7.4). Период применяется к списку так же, как к «По делам».
- Список показывает все дела периода и прокручивается, без усечения «первые N». Дефолт периода — «всё время».

```
   «Ещё» — не экран, а меню: Настройки, Экспорт данных, Импорт данных, О приложении.
   Подписи табов — короткие (i18n nav.tab.*): «Стата» вместо «Статистика».
   На десктопе таб-панели нет: те же пункты в drawer + overflow в AppBar (ТЗ §5.1).
```

### 9.4 Пустые состояния (Empty states)

Дела:

```
       ┌─────────────┐
       │   📋        │
       │  Пусто      │
       │ Создайте    │
       │ первое дело │
       └─────────────┘
         [ + Дело ]
```

Дни:

```
       ┌──────────────┐
       │   📅         │
       │ Пока нет     │
       │ дней         │
       └──────────────┘
       [ + Новый день ]
```

Статистика:

```
       ┌──────────────┐
       │   📊         │
       │ Данных пока  │
       │ нет.         │
       │ Завершите    │
       │ первый день. │
       └──────────────┘
```

Пустой день (FR-D-6):

```
       ┌───────────────────────────────┐
       │       Сегодня                 │
       │   23 сентября · пн            │
       │                               │
       │  На этот день нет плана.      │
       │  День уже открыт пустым.      │
       │  Создайте план дня в разделе  │
       │  «Дни» или возьмите дело      │
       │  из списка.                   │
       │                               │
       │  [ Создать день ]             │
       │  [ Взять дело → ]             │
       └───────────────────────────────┘
```

Пустой день уже существует виртуально (в Dexie его нет) и не пишется в историю, пока не материализован размещением или завершением либо не заменён днём по плану (ТЗ FR-D-6). «Создать день» открывает `/days?create=<дата>` и форму `DayPlanForm` с этой датой; после сохранения план на сегодня заменяет виртуальный день. Если после перезагрузки плана на дату по-прежнему нет — пользователь видит то же состояние, а не «потерянный» день. Когда в дне уже есть дела, этот блок не показывается: в шапке остаётся «Без плана».

## 10. Взаимодействия (interaction map)

```
                        ┌──────────────┐
                        │  DayBoard    │ ←—— стартовый экран
                        │   (Сегодня)  │
                        └──────┬───────┘
              ┌────────────────┼─────────────────┐
              ↓                ↓                 ↓
       ┌────────────┐  ┌──────────────┐  ┌──────────────┐
       │ TasksPage  │  │ DaysPage     │  │ StatsPage    │
       │ (Дела)     │  │ (Дни)        │  │ (Статистика) │
       └─────┬──────┘  └──────┬───────┘  └──────┬───────┘
             ↓                ↓                 ↓
       ┌────────────┐  ┌──────────────┐  ┌──────────────┐
       │ TaskForm   │  │ DayPlanPage  │  │ TaskStats    │
       │ (диалог)   │  │ (редактор)   │  │ (страница)   │
       └────────────┘  └──────┬───────┘  └──────────────┘
                              ↓
                       ┌──────────────┐
                       │ DayPlanForm  │
                       │ (диалог)     │
                       └──────────────┘

       DayBoard → [Завершить и открыть следующий] → CompleteDayDialog
                                      ↓
                            (новый день по плану целевой даты)

       DayBoard → [Открыть план] → DayPlanPage
       DayBoard → [Завершить день] → CompleteDayDialog
                                      ↓
                            (фиксация → история → Stats: recompute)
                                      ↓
                     [Перенести] → carryOvers → новый день (внеплановое дело)

       DayBoard → [Следующий день → / ← Предыдущий день] → openDay
                                      ↓
                            (read-only просмотр сохранённого
                             факта или предпросмотра плана)

       DaysPage → [День] → DayPlanForm → dayPlans.createPlan
                                      ↓
                            (синхронизация открытого «Сегодня»)

       DayPlanPage → [Добавить дело] → PlanTaskPicker
       DayPlanPage → [Настройки дня] → DayPlanForm
                                      ↓
                            (plannedPlacements → синхронизация факта)

       SettingsPage → [Очистить все данные] → settingsStore.clearAll()
                                      ↓
                            (Dexie + localStorage → reinit всех сторов)

       StatsPage → [По дням: день] → DayStatsPage (/stats/day/:date)
                                      ↓
                            (statsStore.loadDayStats: сводка и дела дня)
```

Пересчёт статистики после завершения дня делает сам `cycleStore.completeDay` (FR-S-1), поэтому отдельная стрелка «DayBoard → Stats» не нужна. Импорт данных из SettingsPage переинициализирует сторы тем же путём, что и очистка. Правка плана не переписывает завершённую историю.
