# ToDoDay — Wireframes ключевых экранов

> **Части документации:** [ТЗ](ТЗ-ToDoDay.md) · [Вайрфреймы](Вайрфреймы-ToDoDay.md) · [Контракты](Контракты-ToDoDay.md) · [Скаффолд](Скаффолд-ToDoDay.md) · [Приёмка MVP](Приёмка-ToDoDay.md) · [Журнал правок](Журнал-правок-ToDoDay.md) · [README документации](../README-Docs.md) · [README приложения](../README.md)

Ниже — детальные макеты с аннотациями. Формат: ASCII-схемы + легенда элементов + поведение в состояниях (default / empty / loading / error) + адаптив (mobile / desktop).
Условные обозначения на схемах:

- [ ] — кнопка / кликабельный элемент

- ( ) — radio / чекбокс

- ▾ — dropdown

- ▲▼ — сортировка

- ⚠ — конфликт / предупреждение

- ● — цветовой индикатор дела / дня

- ⋮ — контекстное меню

## 1. Экран «Сегодня» (DayBoard) — основной

### 1.1 Mobile (default)

```
┌─────────────────────────────────────────┐
│ ☰  ToDoDay                      🌙  ⋮   │  ← AppBar: меню, тема, overflow
├─────────────────────────────────────────┤

│  Рабочий день ● · 08:00 – 22:00         │  ← Имя шаблона + акцентный цвет
│  [Следующий день →]   [Завершить день]  │  ← Primary actions
├─────────────────────────────────────────┤
│  ⚠ 1 конфликт                           │  ← число пар Conflict, не карточек

│ 09:30 ┃ │▌Созвон    ●выс  30м  ⚠  │    │

│ 09:45 ┃                                 │

│  ...  ┃                                 │
```

Аннотации:

- Сетка: 15-мин шаг, крупные линии каждые 30 мин, часовые жирнее.

- Автоскролл к текущему времени при открытии (маркер «сейчас» — красная линия).

- Маркер текущего времени — горизонтальная линия через всю ширину с точкой.

- Долгий тап (mobile) или правый клик (desktop) на PlacementCard — контекстное меню.

Поведение:

- Левая панель — ширина 280–320 px, сворачиваемая.

- Дела из левой панели перетаскиваются на сетку (snap к 15 мин).

- Уже до 1024 px второй колонки нет: список дел живёт на экране «Дела», а не в drawer. Drawer по ☰ на этой ширине — навигация, не панель дел (ТЗ §5.1, вайрфреймы §11).

### 1.3 Состояния

| Состояние | Что показываем |
| --- | --- |
| Loading | Skeleton-сетка серого цвета + shimmer |
| Empty (нет дел) | Сетка + центральный CTA «Возьмите дело из списка →» |
| Empty (пустой день по FR-D-6) | Сетка + CTA «Настроить день» и «Взять дело». День виртуален: в Dexie его нет, activeInstanceId = null; состояние переживает перезагрузку и не создаёт записи в истории |
| День завершён | Доска только для чтения: drag, меню размещений и «Завершить день» недоступны (`DAY_NOT_ACTIVE`). В шапке, пока живёт снапшот сессии, кнопка «Отменить завершение» (FR-E-3). «Следующий день →» скрыта, пока день не active |
| Шаблон удалён (FR-D-4) | В шапке вместо имени шаблона — «Шаблон удалён» (i18n `day.templateDeleted`), акцентный цвет нейтральный |
| Error (БД недоступна) | Баннер сверху + кнопка «Повторить» |

### 1.4 Компоненты-детали
PlacementCard — states:

```
Default:           ▌Название дела         ●приоритет   30м
Now (визуально):   ▌▶ Название дела       ●приоритет   30м   [•••]
Done:              ▌✓ Название дела (зачёркнуто)  ●        30м
Skipped:           ▌✗ Название дела (приглушено)  ●        30м
Conflict:          ▌Название дела  ⚠      ●приоритет   30м
```

Context menu (long-press / right-click), он же клавиатурный путь (Enter/Space на карточке, FR-B-7):

```
┌─────────────────────────────┐
│ ✓ Отметить выполненным      │  ← или «Снять отметку», если уже done
│ ✗ Отметить пропущенным      │  ← или «Снять отметку», если уже skipped
│ ─────────────────────────── │
│ ⏱ Изменить длительность     │
│ 🔄 Заменить дело            │
│ ➡ Переместить в слот…       │  ← клавиатурная альтернатива drag-and-drop (FR-B-2)
│ 🗑 Убрать из дня            │
└─────────────────────────────┘
```

▶ — не статус. Рисунок, пока локальное время внутри интервала размещения. `Placement.status` не меняется (FR-B-6). Чекбокса на карточке нет.

Аннотации доступности: карточка — `role="button"`, `tabindex="0"`, `aria-pressed="true"` только пока её тащат, `aria-label` вида «Зарядка, 08:15–08:30, выполнено». Список «Переместить в слот…» — `role="list"`, пункт — `role="listitem"`. Стрелки работают внутри этого списка. Перенос объявляется через `aria-live` («Зарядка перемещена в 09:00»).

## 2. Экран «Дела» (TasksPage)

### 2.1 Mobile

```
┌─────────────────────────────────────────┐
│ ☰  Дела                         🌙  ⋮   │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────────────┐ │
│ │ 🔍 Поиск по названию...             │ │
│ └─────────────────────────────────────┘ │
│ [Приоритет ▾]  [Цвет ▾]  [Показать архивные ☐] │
├─────────────────────────────────────────┤
│ Сортировка: Название ▲▼    Создано ▾    │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────────────┐ │
│ │ ▌Зарядка                  ●выс      │ │
│ │   15 мин · выполнено 12 / пропущ. 3 │ │
│ │                            [⋮]      │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ▌Почта                   ●сред      │ │
│ │   30 мин · выполнено 8 / пропущ. 5  │ │
│ │                            [⋮]      │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ▌Созвон                  ●выс       │ │
│ │   30 мин · не размещалось            │ │
│ │                            [⋮]      │ │
│ └─────────────────────────────────────┘ │
│  ...                                    │
├─────────────────────────────────────────┤
│                              [ + Дело ] │  ← FAB
└─────────────────────────────────────────┘
```

Карточка дела:

- Полоса цвета слева (4 px).

- Название — 1 строка, ellipsis.

- Приоритет — бейдж справа.

- Длительность + мини-сводка (done/skipped).

- [⋮] — контекстное меню.
Контекстное меню карточки:

```
┌──────────────────────────────┐
│ ✏️ Редактировать             │
│ 📋 Дублировать               │
│ 📊 Статистика дела           │
│ ──────────────────────────── │
│ 🗄 Архивировать              │  ← FR-T-3 (soft-delete)
│ 🗑 Удалить                   │  ← FR-T-6: только для архивного дела
└──────────────────────────────┘
```

Правило разделения действий (FR-T-3 / FR-T-6): «Архивировать» доступно всегда и обратимо (в том же меню у архивного дела — «Вернуть из архива»). «Показать архивные» выключен — в списке только живые дела; включён — живые и архивные вместе. «Удалить» показывается только у архивной строки (фильтр при этом включён, иначе архивных строк не видно); нажатие требует подтверждения «Удалить дело из архива безвозвратно?». У неархивного дела пункт скрыт, а action возвращает CONSTRAINT_VIOLATION.

Аннотации к таблице:

- Иконка 🗑 (удалить) в колонке «Действия» активна только для архивных строк; для остальных она либо скрыта, либо задизейблена с подсказкой «Сначала архивируйте дело» (FR-T-6).
- Дело без размещений («Созвон») не попадает в `perTask` (ТЗ FR-S-2, FR-T-4). На экране дел — «не размещалось», не «—» и не 0%. «—» остаётся только у рейта null при placed > 0 на экране статистики.

## 3. Экран «Дни» (DaysPage) — список шаблонов

### 3.1 Mobile

```
┌─────────────────────────────────────────┐
│ ☰  Дни                          🌙  ⋮   │
├─────────────────────────────────────────┤
│ Порядок шаблонов (перетащите):           │
│                                          │
│ ┌─────────────────────────────────────┐ │
│ │ ⠿ 1  Рабочий день ●            [⋮]  │ │
│ │     08:00–22:00 · Пн, Вт, Ср, Чт, Пт│ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ⠿ 2  Спорт-день ●              [⋮]  │ │
│ │     06:00–10:00 · 1, 15 числа       │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ⠿ 3  Выходной ●                [⋮]  │ │
│ │     09:00–23:00 · Сб, Вс            │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ⠿ 4  Свободный день ●          [⋮]  │ │
│ │     10:00–20:00 · без привязки      │ │
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│                        [ + Шаблон дня ] │  ← FAB
└─────────────────────────────────────────┘
```

Карточка шаблона:

- Ручка ⠿ для drag-and-drop сортировки.

- Номер на карточке — это `order + 1`. `order` общий для всех шаблонов; по циклу идут только шаблоны «без привязки» (FR-C-2). Перетаскивание календарного шаблона меняет номера соседних циклических.

- Название + акцентный цвет.

- Диапазон времени.

- Правило (человекочитаемое): «Пн, Вт, Ср…», «1, 15 числа», «Без привязки».

Число дел и «часы занято» на карточке шаблона не показываются: у шаблона нет размещений (они живут в экземпляре дня).
Контекстное меню шаблона:

```
┌──────────────────────────┐
│ ✏️ Редактировать         │
│ ──────────────────────── │
│ 🗑 Удалить               │
└──────────────────────────┘
```

«Дублировать» и «Предпросмотр доски» в MVP нет: отдельных actions и состава дня внутри шаблона нет (ТЗ §10 — пресеты позже).

### 4.2 Валидация (inline, у поля)

| Поле | Правило | Сообщение |
| --- | --- | --- |
| Название | 1–50 символов | «Введите название (до 50 символов)» |
| Время | `HH:mm`, минуты кратны 15, `00:00–23:45`, end > start, ≥ 1 ч | «Конец дня должен быть позже начала» / «Некорректное время» |
| Цвет | `#RRGGBB` | «Цвет: HEX #RRGGBB» |
| Правило | не пустое | «Выберите хотя бы один день/число» |
| Конфликты | нет пересечений | «Пересечение с шаблоном X» |

Чипы Пн–Вс при `firstDayOfWeek = 1` начинаются с вс; индексы в `RepeatRule` от этого не меняются (FR-SET-9). Неблокирующая строка `days.cyclicUnreachable` появляется в двух случаях, сохранение при этом не отменяется: weekdays закрыли все 7 дней и циклические шаблоны уже есть; либо сохраняется циклический шаблон, когда неделя уже закрыта (FR-C-2).

## 6. Диалог завершения дня (CompleteDayDialog)

```
┌─────────────────────────────────────────┐
│  Завершить день?                    ✕   │
├─────────────────────────────────────────┤
│  Понедельник · 23 сентября              │
│  Рабочий день                            │
│                                          │
│  Отметьте, что успели сделать.           │
│  Всё неотмеченное будет помечено         │
│  пропущенным.                            │
│                                          │
├─────────────────────────────────────────┤
│  Выполнено: 5 из 8                       │
│                                          │
│  (•) ▌Зарядка            08:15   15м    │
│  (•) ▌Почта              09:15   30м    │
│  ( ) ▌Созвон             09:30   30м    │  ← не отмечено
│  (•) ▌Чтение             12:00   60м    │
│  (•) ▌Обед               13:00   45м    │
│  ( ) ▌Спорт              18:00   60м    │
│  (•) ▌Дневник            21:00   30м    │
│  ( ) ▌Планерка           21:30   30м    │
│                                          │
│  Быстрые: [Отметить всё] [Снять всё]    │
│                                          │
├─────────────────────────────────────────┤
│  [Вернуться к дню]  [Подтвердить]        │
└─────────────────────────────────────────┘
```

Поведение:

- По умолчанию: done → чекбокс стоит, pending → снят, skipped → снят. Нераспределённые входят в список без времени.

- Снятие галочки с ранее done — при подтверждении станет skipped.

- Кнопка «Вернуться к дню» — закрывает диалог без фиксации.

- После подтверждения — тост «День завершён» (5 с) с кнопкой «Отменить» и такая же кнопка в шапке доски, пока живёт снапшот сессии (FR-E-3). Отмена удаляет день, созданный этим завершением, даже если в него уже положили дела.

- Авто-триггер: доп. опция «Пропустить диалог в этот раз». Она не пишет настройки. Постоянный тумблер — только экран настроек (вайрфреймы §8, поле askToCompleteOnNewDay). «Вернуться к дню» у авто-диалога тоже ставит разовый пропуск до перезагрузки.

- Пустой (виртуальный) день: диалог не открывается автоматически — отмечать нечего. Кнопка «Завершить день» на доске остаётся доступной: подтверждение сохраняет экземпляр без размещений в историю (FR-D-6).

- Сдвиг («Следующий день →»): в заголовке диалога добавляется подпись, что после подтверждения начнётся новый день. Для `early` дата нового дня — завтра, для `overdue` — сегодня; шаблон берётся на ту же дату (ТЗ §2.8).

### 7.1 Mobile

```

│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────┐ │
│ │  48    │ │  32    │ │  16    │ │67% │ │
│ │размещ. │ │выполн. │ │пропущ. │ │рейт│ │
│ └────────┘ └────────┘ └────────┘ └────┘ │
├─────────────────────────────────────────┤
│ По делам                     Сорт: [▾]  │
│ ┌─────────────────────────────────────┐ │
│ │ ▌Зарядка                  ●выс      │ │
│ │ 12 вып. · 3 проп.                   │ │
│ │ ████████████░░░  80%                │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ▌Почта                    ●сред     │ │
│ │ 8 вып. · 5 проп.                    │ │
│ │ ████████░░░░░░░  62%                │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ ▌Спорт                    ●выс      │ │
│ │ 0 вып. · 4 проп.                    │ │
│ │ ░░░░░░░░░░░░░░░  0%                 │ │
│ └─────────────────────────────────────┘ │
│  ...                                    │
└─────────────────────────────────────────┘
```

Про строки таблицы (ТЗ FR-S-2):

- В список попадают только дела, у которых есть хотя бы одно размещение в завершённых экземплярах выбранного периода. Строки «0 размещено / 0 выполнено» не существует: дело, которое не размещали вовсе или размещали только вне периода, в таблицу не показывается.
- «0 вып. · 4 проп. · 0%» — это дело с размещениями в периоде, все из которых пропущены (placed = 4, done = 0, skipped = 4). Рейт 0% и 0/0 — разные вещи: 0/0 даёт прочерк «—» и в таблицу не попадает, потому что размещений в периоде нет.
- Прочерк «—» на прогресс-баре остаётся только для вырожденного случая placed > 0 при done + skipped = 0 (например, всё ещё pending — в MVP для завершённых экземпляров недостижимо).
- Итоговая сводка — четыре числа `OverallStats` (размещено, выполнено, пропущено, рейт), те же на узком экране и на десктопе. Список показывает все дела периода и прокручивается, без усечения «первые N».
- Дефолт периода — «всё время».

```
       ┌───────────────────────────────┐

```

Когда в дне уже есть дела, этот блок не показывается: в шапке остаётся «Без шаблона».

## 10. Взаимодействия (interaction map)

```
                        ┌──────────────┐
                        │  DayBoard    │ ←—— стартовый экран
                        │   (Сегодня)  │
                        └──────┬───────┘
              ┌────────────────┼─────────────────┐
              ↓                ↓                 ↓
       ┌────────────┐  ┌──────────────┐  ┌──────────────┐
       │ TasksPage  │  │ DaysPage     │  │ StatsPage    │
       │ (Дела)     │  │ (Шаблоны)    │  │ (Статистика) │
       └─────┬──────┘  └──────┬───────┘  └──────┬───────┘
             ↓                ↓                 ↓
       ┌────────────┐  ┌──────────────┐  ┌──────────────┐
       │ TaskForm   │  │ DayTemplate  │  │ TaskStats    │
       │ (диалог)   │  │ Form (диалог)│  │ (страница)   │
       └────────────┘  └──────────────┘  └──────────────┘

       DayBoard → [Завершить день] → CompleteDayDialog
                                        ↓
                              (фиксация → история → Stats: recompute)

       DaysPage → [Сохранить шаблон] → cycleStore.resolveCurrentDay({ force: true })
                                        (только если текущий день виртуальный: FR-D-6)

       SettingsPage → [Очистить все данные] → settingsStore.clearAll()
                                        ↓
                              (Dexie + localStorage → reinit всех сторов)
```

Пересчёт статистики после завершения дня делает сам cycleStore.completeDay (FR-S-1), поэтому отдельная стрелка «DayBoard → Stats» не нужна. Импорт данных из SettingsPage переинициализирует сторы тем же путём, что и очистка.
